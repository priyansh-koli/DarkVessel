Guide

Find out why a vessel was reported dark

Ships must broadcast their position over AIS. Radar sees them whether they do or not. The viewer puts one radar scene next to what AIS declared at the moment it was taken, and shows, for every vessel it found, what explains it or what doesn't.

Five-step tour

Each step opens the viewer already set up to show one behaviour. The scene is a synthetic fixture built so that each of its five vessels takes a different path through the pipeline.

  1. Read a verdict

    Select any box on the scene or row in the table. The inspector on the right says, in words, which declaration explained it, how far apart they were, and what the position rests on. Detection 2's position was interpolated between two reports. Its nearest single report sits about 900 m away, far enough on its own to call it dark.

    Open detection 2 →

  2. Switch off the azimuth correction

    Radar draws a moving ship displaced along the satellite's track. The dashed orange line shows that shift. Turn the correction off and detection 3, the fast vessel, falls out of tolerance: 4 matched / 1 dark becomes 3 matched / 2 dark.

    See detection 3 go dark →

  3. See why the dark vessel stays dark

    Detection 5 has a declaration only 170 m away, inside the 200 m tolerance. It's still dark because matching is one-to-one: that declaration fits detection 4 better (30 m). A greedy matcher that let one declaration explain two ships would hide this vessel.

    Open detection 5 →

  4. Tighten the tolerance

    At 25 m, detection 4's declaration (about 30 m off) no longer counts. A dark count always comes with the tolerance it was measured at, and the table and inspector both show it.

    Try a 25 m tolerance →

  5. Register a fixed structure

    Turbines and platforms show up on every pass. Select Register by clicking the scene, then click a dark detection. It turns structure, and no matched vessel is ever touched: structure exclusion runs after matching.

    Register one under detection 5 →

The four statuses

Matched

A declaration, placed at the acquisition instant, explains this detection within the tolerance.

Dark

AIS was searched and nothing explains it. This is a claim about the evidence searched, not a verdict about the ship.

Structure

It stands on a registered fixed position, so it isn't counted as a vessel. Only dark detections can become structures.

Unsearched

No AIS archive was supplied, so nobody tried to explain it. Missing data is never reported as dark.

Controls

Radar or SAR image

The scene opens as a radar display: range rings from the scene centre, bearings from north, and a sweep that brightens each contact as it passes. A matched vessel is drawn as a hull pointing along its AIS course, with an arrow showing where it will be in 20 seconds. A dark contact is a pulsing red diamond. We can't know its heading, so none is drawn. SAR image shows the radar pixels exactly as they are. Pause sweep stops the animation, which also stays off if your system asks for reduced motion.

Match tolerance

How far a declared position may sit from a detection and still explain it. Lower is stricter and reports more dark vessels.

Max AIS gap

How old a lone report may be and still place a vessel. Beyond it the vessel isn't placed at all, so it can't explain anything. Reports that bracket the acquisition are always interpolated.

Azimuth-shift correction

Moves each declaration to where the radar would have drawn that vessel, given its speed, before matching.

Brightness threshold

The stand-in detector's cut-off. Lower finds fainter targets. A trained detector would replace this.

Structure register

Known fixed positions, such as a turbine list. A dark detection within the same-position tolerance of one becomes a structure.

Counts, table, Share and export

Click a count card to filter the scene and table to that status. Share copies a link that reopens the exact view: every control, every registered position and the selected detection. CSV and JSON download the current run.

FAQ

Is this real satellite data?

Not yet. The published viewer runs on a synthetic scene of five vessels, built so each one exercises a different branch of the pipeline. The same code runs on a real Sentinel-1 scene and a DMA AIS day file.

The badge says "Static build". What does that mean?

The published site has no server. When it was built, the pipeline was run for every position the controls can take, and each distinct result was saved. Moving a control looks up the matching run, so it responds instantly. Run it locally for a live pipeline (see below). Results are identical.

Why does max AIS gap jump in steps on the published site?

To keep the static build small, it pre-computes a set of gap values (1 to 120 minutes) rather than every minute. The live server accepts any value.

Does "dark" mean the ship is doing something illegal?

No. It means no declaration explained the detection within the stated tolerance, from the AIS the search actually had. The AIS panel shows what was searched and what cleaning removed. The dark call rests on that.

Can I share a specific finding?

Yes. Select Share above the scene. A panel shows the link and lists what it restores: the controls, the register and the selected detection. The link is copied for you. If your browser blocks copying (some embedded previews do), the link is already selected, so press ⌘C or Ctrl+C.

Run it yourself

No credentials, weights, GPU or network needed:

pip install -e ".[web]"
darkvessel synthesise --out data/synthetic
darkvessel serve --config configs/pipeline.yaml    # live, at http://127.0.0.1:8000

To publish your own static copy, darkvessel render --config configs/pipeline.yaml --out site writes a folder any static host can serve.
